## 1. Technical Problem Statement

In automated administrative document processing (GovTech, welfare distribution, legal compliance), forms are generated by combining information extracted from heterogeneous, independently issued identity documents (e.g., National ID / Aadhaar, Educational Marksheets, Income Certificates).

Existing industry solutions suffer from two catastrophic failure modes:
1. **Destructive Overwriting**: An extracted field $F$ is treated as a scalar register. When Document $D_1$ yields $v_1$ and Document $D_2$ yields $v_2$, systems either silently overwrite $v_1$ with $v_2$ or take an arbitrary majority vote, destroying provenance and legal auditability.
2. **Confidence Conflation**: Systems conflate raw optical recognition confidence $\mathcal{C}_{ocr}$ with factual or legal truth. An OCR engine reporting 99% glyph confidence on an incorrectly issued certificate causes downstream portals to accept the faulty data, leading to statutory rejection.

## 2. Core Mathematical & Algorithmic Formulations

### 2.1 Multi-Dimensional Reliability Tensor

Rather than reducing field confidence to a single scalar, GramSathi AI evaluates field reliability as a 4-dimensional tensor:

$$\mathbf{R}(F) = \Big\langle \mathcal{C}_{ocr}(F), \; \mathcal{C}_{consist}(F), \; \mathcal{C}_{audit}(F), \; \mathcal{C}_{rules}(F) \Big\rangle$$

Where:
- **$\mathcal{C}_{ocr}(F) \in [0, 1]$**: The harmonic mean of token-level glyphic confidences emitted by the OCR engine for candidate value $v$:
  $$\mathcal{C}_{ocr} = \frac{N}{\sum_{i=1}^N c_i^{-1}}$$
- **$\mathcal{C}_{consist}(F) \in [0, 1]$**: Mutual corroboration metric across independent documents $D_1, D_2, \dots, D_k$:
  $$\mathcal{C}_{consist} = \frac{2}{k(k-1)} \sum_{i < j} \text{Sim}\big(v_i, v_j\big)$$
  where $\text{Sim}(v_i, v_j)$ is the normalized string and phonetic similarity between normalized representations.
- **$\mathcal{C}_{audit}(F) \in \{0, 1\}$**: Discrete boolean reflecting explicit human verification by the citizen or authorized operator.
- **$\mathcal{C}_{rules}(F) \in \{0, 1\}$**: Deterministic satisfaction of scheme-specific statutory predicates ($P_{scheme}(v) = \text{True}$).

### 2.2 Formal State Transition Function

Let $S$ be the finite set of field reliability states:
$$S = \{\text{EXTRACTED}, \text{NEEDS\_REVIEW}, \text{CONFLICTED}, \text{USER\_CONFIRMED}, \text{USER\_CORRECTED}, \text{ELIGIBLE\_FOR\_DRAFT}\}$$

The transition function $\delta: S \times \mathbf{R} \rightarrow S$ is defined as:

$$\delta(s, \mathbf{R}) = \begin{cases}
\text{CONFLICTED} & \text{if } \mathcal{C}_{consist} < \tau_{conflict} \text{ and } k \ge 2 \\
\text{NEEDS\_REVIEW} & \text{if } \mathcal{C}_{ocr} < \tau_{ocr} \text{ or } \tau_{conflict} \le \mathcal{C}_{consist} < 1.0 \\
\text{ELIGIBLE\_FOR\_DRAFT} & \text{if } (s \in \{\text{USER\_CONFIRMED}, \text{USER\_CORRECTED}\} \lor \mathcal{C}_{consist} = 1.0) \land \mathcal{C}_{rules} = 1 \\
s & \text{otherwise}
\end{cases}$$

### 2.3 Gated Draft Generation Condition

An official application draft $\mathcal{D}$ can be generated if and only if every mandatory field $F_i \in \mathcal{F}_{mandatory}$ satisfies the draft-eligibility invariant:

$$\text{CanGenerateDraft}(\mathcal{D}) \iff \forall F_i \in \mathcal{F}_{mandatory}: \; \text{State}(F_i) = \text{ELIGIBLE\_FOR\_DRAFT}$$

If any field fails this invariant, the generation controller aborts draft synthesis, returns an HTTP 422 Unprocessable Entity, and generates targeted user guidance.

## 4. Patent Claims & Research Defense

The primary claims for patentability and research evaluation focus on:
1. **The System Architecture**: Decoupling canonical application fields from underlying evidentiary observations across multi-document intake pipelines.
2. **The Conflict Classification & State Gating Method**: An algorithmic process that categorizes textual and numeric variations across independent official documents, transitions fields through an auditable reliability state machine, and strictly prevents non-reconciled fields from reaching export state.
3. **The Dependency-Aware Scheme Revalidation Method**: Maintaining a dynamic DAG of statutory predicates linked to extracted evidence nodes, ensuring changes propagate selectively to dependent eligibility checks without full re-computation.
